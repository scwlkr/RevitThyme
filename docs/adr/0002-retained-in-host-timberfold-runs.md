# Retained in-host TimberFold runs

TimberFold uses short accepted run handles, a retained in-host coordinator and file-backed evidence, with typed extraction/finalization queued to Revit callbacks and immutable data passed to background computation. A separate worker would improve crash isolation but adds deployment and IPC surfaces; bounded managed geometry, cancellation and explicit resource limits keep the first implementation within the existing host architecture. Status/cancel bypass the Revit queue, no transaction crosses an await, and native commit and filesystem publication remain separate: publication failure after native assimilation is unconfirmed and must never trigger a blind retry.

Protocol 6 derives separate status and cancellation pipe names from the validated process/session binding. Both retain the same per-user ACL, remote-client rejection, server-PID verification and session/protocol handshake as ordinary operations. Each control channel accepts only its named operation. This preserves ordinary request sequencing while a native callback or a large recovered-status read is outstanding. A general pool of concurrent ordinary connections could also provide control responsiveness, but changes the transport sequencing/security surface more broadly than these two bounded channels. MCP selects the current immutable client/binding pair under a brief state lock and releases it before control RPCs; it never retargets an in-flight control call.

Start pipe listener loops explicitly on a background task. Revit startup supplies a Windows Forms synchronization context: starting an async listener directly there captures the UI thread at its first await and defeats separate control channels. The actual pinned-host regression enters a marked three-second native callback, then requires status/cancel to finish before that callback returns. The former listener startup delayed both by about 2,999 ms; background startup reduced observed control calls to about 5–6 ms. Native extraction/finalization still enter only the ExternalEvent callback.
