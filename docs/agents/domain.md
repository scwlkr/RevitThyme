# Domain docs

Use root [CONTEXT.md](../../CONTEXT.md) as the single domain glossary and `docs/adr/` for consequential decisions. `GLOSSARY.md` redirects to the preserved toolkit definitions and TimberFold terms there. Read relevant ADRs before designing in that area. Missing files do not block exploration. Create glossary entries only when terms are resolved; keep implementation details in specs. Create ADRs only for hard-to-reverse, surprising decisions with real trade-offs. Surface contradictions with existing decisions before changing direction.
